# Repo Autopilot

An open-source GitHub dashboard and future development orchestrator for any repository. MIT licensed, with no Debatt-AI-specific configuration.

## Web dashboard (GitHub Pages)

[Open the dashboard](https://cryptomanxxx.github.io/repo-autopilot/) — this address becomes available after the Pages workflow is merged, Pages is enabled, and deployment succeeds.

For **cryptomanxxx/repo-autopilot**, the hosted dashboard reads a saved public JSON snapshot generated by GitHub Actions with the built-in `GITHUB_TOKEN`. The browser reads public snapshots without authenticated GitHub API calls. A dedicated data workflow publishes snapshots on the `dashboard-data` branch independently of Pages deployments; the browser uses the newer of that snapshot and the Pages fallback. No Vercel, separate server, login or user-supplied token is needed. The workflow refreshes after PR changes, review/comment events and completed CI, plus a scheduled refresh every 15 minutes (GitHub may delay scheduled runs). Reactions have no dedicated event, so Codex thumbs-up may appear on the next scheduled refresh. The snapshot timestamp is visible; green readiness is downgraded to unknown after 30 minutes. Failed collection leaves the previous snapshot intact.

Other public repositories still use GitHub's anonymous API directly: enter `owner/repository` or a full GitHub URL. This fallback fetches 5 recent PRs and 15 workflow runs, uses up to 43 REST calls, and caches results in memory for 60 seconds. GitHub's anonymous API limit applies. Private repositories are available only through local server mode.

### Enable publishing

In **Settings → Pages → Build and deployment → Source**, select **GitHub Actions**. After merging the Pages workflow into `main`, check **Actions → Deploy dashboard to GitHub Pages**. If needed, use **Run workflow**. The completed deployment reports the exact URL. Put that URL into **About → Edit → Website**.

Pages deploys on main pushes or manual dispatch and uploads static assets with a fallback snapshot in `dist/data/snapshot.json`; no `.env`, token or server is published. Snapshot generation refuses private repositories and excludes raw comments and review bodies. The workflow always checks out the trusted default branch, never PR code, for snapshot publishing. Assets use relative paths so the dashboard works under the `/repo-autopilot/` project path. This static dashboard does not host MCP or autonomous workers.

```sh
npm run build
# For a local static preview:
python -m http.server 8080 --directory dist
```

## v0.1: real GitHub dashboard

View the most recently updated pull requests (5 hosted, 10 local), opened/merged timestamps, concise Codex progress, head-commit check/status results, and 15 recent GitHub Actions runs. Links open the corresponding GitHub discussion or workflow. Empty states and API errors are shown explicitly.

Automatic merge is **off**. The optional owner-triggered Actions agent prepares a branch for review; it does not execute generated code or merge changes. A successful CI indicator is informational: it does not establish branch protection, resolved conversations, current review approval, or merge eligibility. Review histories and comments are limited to 100 entries per endpoint, with truncation warnings. Codex status includes PR reactions, review summaries and comments. A thumbs-up is shown as current only when paired with a completed Code Review summary for the PR head commit and a reaction timestamp at or after completion. Current-commit findings and explicit no-findings comments are supported; older or unlinked activity is labeled unverified. A newer review request invalidates the earlier status. Incomplete histories never establish a clear result. These are informational signals, not formal GitHub approvals or merge authorization.

## Run

Requires Node.js 22 or later. No dependencies or paid AI API are required for this version.

```sh
cp .env.example .env
# Optionally set GITHUB_TOKEN in .env for private repos / higher limits.
npm start
```

Open http://127.0.0.1:3000 and enter `owner/repository` or a full GitHub repository URL. Public repositories can be read without a token, subject to GitHub's anonymous rate limit. Private repositories require a token with read access to the selected repositories and Metadata, Pull requests, Issues, Actions, Checks and Commit statuses. Credentials remain on the server; the browser receives only dashboard data. Snapshots are cached for 60 seconds with at most 20 repository entries.

The server binds to loopback and is intended for local development. Do not expose this token-backed server publicly: multi-user authentication, repository authorization, rate limiting and production hosting have not been implemented.

```sh
npm run check
npm test
```

## Product roadmap

1. Dashboard foundation (this release).
2. GitHub App authentication, explicit repository selection, full pagination and precise Codex review/reaction tracking.
3. MCP tools and a ChatGPT-compatible dashboard component, tested against current OpenAI documentation and supported clients. This repository is not yet an installable ChatGPT plugin.
4. Optional external orchestration: review feedback → code-agent fix → CI → re-review. Explicit per-repository opt-in, bounded retries, audit history and human stop controls.
5. Optional merge policy enforcing current-head review approval, required checks, branch rules and resolved feedback.

ChatGPT UI integration and background work are separate components: a dashboard presents state; an external worker continues tasks when the chat is closed. Future code-agent use may require paid API access or other compute; no subscription coverage or free hosting is assumed.


## PR progress and merge readiness

PR cards show review acknowledgement, completion for the latest code, Codex outcome, completed review rounds, commits after review and merge readiness. Confirmation summaries and raw technical feedback are hidden; use the GitHub history link for details.

Review counts are **lower bounds**: GitHub edits Codex summaries in place, so some older clean rounds cannot be recovered. Review submissions, outcome comments and summaries for the same commit within 10 seconds are deduplicated. Commits after review counts subsequent commits in the PR after the earliest reviewed commit found in its history; it does not prove that feedback was fixed. Missing/truncated histories show unknown update counts.

Readiness distinguishes merged, closed, known blockers and unverified state. Anonymous live lookups can identify drafts, conflicts, CI failures and Codex findings, but cannot fully verify resolved threads and protected-branch requirements. It therefore does **not** show green merge readiness from CI alone.

The authenticated Actions snapshot and local token-backed mode additionally ask GitHub GraphQL for current-head merge state, review decision and conversation resolution. Ready requires current Codex clearance, complete successful CI, conflict-free merging, GitHub CLEAN state, no missing approvals or requested changes, and all conversations resolved. Truncated thread results or API errors stay unverified. This is a snapshot, never permission to bypass GitHub rules or an automatic merge action. The token must support the GraphQL read operations; otherwise readiness stays unknown.

## Activity flow and filters

PR rows expand to a chronological activity flow: PR opened, explicit Codex review requests, observed running/completed reviews, subsequent commits, current-commit Codex thumbs-up and merge. This is observed history, not proof that an agent fixed a finding. Commit timestamps may precede their push, summaries are edited in place, and older/truncated events may be missing. No missing steps are invented.

Filter PRs by open, needs attention, merged or all, and workflows by CI, deployment or all. On wide screens, shared column headings reduce repetition. The hosted Repo Autopilot view rereads saved data every 20 seconds when a fetched PR is open, otherwise every minute while visible, preserves expanded rows, and shows data age. It does not stream GitHub events in real time: Actions publication and scheduled refresh delays still apply. Other repositories retain manual anonymous lookup.

Historical P1/P2 counts use top-level Codex finding comments with explicit priority badges, deduplicated by comment identity. Replies and summary text do not count as new findings. Counts remain after resolution; incomplete history is marked as a lower bound. The separate unresolved-thread count includes all reviewers and is unverified if authenticated thread retrieval fails. #Commits counts commits after review, not the number of findings fixed.

## Actions agent tasks

The hosted Repo Autopilot view includes a task box and the latest five owner tasks found among the 30 most recently updated issues. Write an instruction and choose **Continue on GitHub**. GitHub opens a prefilled public issue; submit it as the repository owner to start the agent. The browser stores no credentials. Your task and agent responses are public. The owner-only worker runs trusted default-branch code with `GROQ_API_KEY` from Actions secrets and uses Groq's `openai/gpt-oss-120b`. Model API usage and limits apply. Requests use at most 6,000 UTF-8 bytes of serialized messages and reserve 1,500 completion tokens to fit the 8,000-token free-tier budget conservatively. The agent sends bounded source excerpts and applies only unique exact replacements against the complete original files. Truncated responses cannot publish a branch.

The worker performs one bounded attempt, reads source through GitHub REST, validates up to eight exact source replacements, and creates `autopilot/task-N`. Allowed edits are existing supplied JS/CSS/HTML/Markdown files in src, public and test, plus README. Agent infrastructure, hidden files, workflows, dependencies and secrets are excluded. Generated code is never executed in the secret-bearing worker. This first version handles small tasks with the supplied source context; it may ask for more information rather than change code. It does not yet automatically iterate over Codex feedback.

Open the task in the dashboard to read replies. If changes are ready, use **Review changes and create PR** and create the PR with your GitHub account. This deliberate confirmation ensures CI and the configured Codex integration receive user-created PR events; PRs created with the built-in Actions token do not normally trigger other Actions workflows. Review and green CI remain required before merging. Close the task issue to request cancellation: the worker checks before publishing a branch, but closing does not undo an already published branch. Failed tasks can be retried by creating a new task; workflow reruns do not duplicate an existing agent attempt.

The dashboard refreshes every 20 seconds while a PR or a queued/working task is visible in saved data. Completed worker runs refresh the data snapshot. GitHub queue delays still apply. This is a task interface with GitHub confirmation, not a continuous authenticated in-page chat; follow-up conversation and automatic fix loops are future work.

For an organization-owned repository, set the repository Actions variable `AUTOPILOT_TASK_USER` to the GitHub login allowed to submit tasks. The worker and snapshot collector use that same account. For a personal repository, the default is the repository owner. Updating this variable requires repository administration access. Existing files omitted from the model context cannot be replaced; the validator checks the complete source tree before creating a commit.

GET /api/v1/state returns generated_at (UTC second precision), counts and lists of running, retrying and blocked issues, codex_totals and rate_limits. Timeout/unavailable errors are JSON payloads from the presenter even when HTTP succeeds. GET /api/v1/:issue_identifier provides detailed data. POST /api/v1/refresh requests an immediate poll/reconciliation cycle and may cause dispatch. Never use refresh in a read-only adapter. No dedicated start/pause/stop routes exist in this inspected router. Do not equate empty running list with verified cessation. Runtime totals are aggregate session seconds, not elapsed wall time. Retry entries may be normal continuations, not failures. Counts are not an exhaustive issue queue or completed experiment history. Raw rate limits are not verified subscription entitlement or monetary cost.

The router's JSON scope does not use the browser pipeline or an explicit authentication plug; endpoint code does not establish an API authorization boundary. Do not expose the upstream service publicly or give the browser direct access. Raw data includes workspace paths, worker hosts, session identifiers, messages, errors and issue URLs. Future integration requires an authenticated private host-side projection, repository identity bound independently to actual tracker/workflow configuration, verified revision, bounded transport and strict server-side scope. The native state payload has no repository identity or revision attestation. Do not trust a user-supplied revision string or infer scope from GH issue IDs. No public raw telemetry, credentials, arbitrary endpoint input or direct Cloudflare-to-localhost assumption.

## Offline implementation

worker/public/symphony-state.js is an unconnected aggregate normalizer for the pinned presenter shape, bounded to 256 KiB and 1000 rows per category. It reconciles counts and list sizes, rejects duplicate issue identities, validates timestamps and numeric totals, handles unavailable payloads separately and discards all raw identifiers, messages, errors, paths and rate-limit details. The revision argument selects a schema, not source authentication. Local age threshold of 180 seconds is a display convention, not a safety guarantee. Unknown queue size, failures, actual cost and verified quota remain null. No dispatch authorization or source verification. No browser wiring, host, deployment, network transport or live request. ## RA-S03A.3 private read preparation

Existing Worker configuration has a private service binding precedent for the optional AI gateway, but no Symphony binding or verified Symphony host. Existing owner authentication and repository access resolver can be reused by a future server-side integration; they do not prove actual Symphony host scope. Cloudflare Workers is not an Elixir/Codex subprocess host. Do not expose native Symphony HTTP endpoints or connect from the browser.

The prepared worker/src/symphony-private-read.js contract requires trusted host assertions for owner authorization, repository access, private host, tracker scope, pinned upstream revision, included capacity, no paid fallback, explicit read approval and expiry. These are assertions only, not a production verification mechanism. With no permit or transport it blocks. A future host-side projection must independently bind repository/revision to actual running configuration, authenticate both ends, enforce a transport timeout, bound streamed bytes before allocation, and return only the exact v1 aggregate envelope. The consumer permits one injected read operation, validates scope/schema/timestamps and bounded bytes, and rejects late responses. No default transport, URL, endpoint, credential, service binding, permit issuer, route or browser wiring is supplied. No refresh or control operations. All results remain source-unverified pending trust-boundary qualification; zero sessions is not verified stop, actual spending and quota stay unknown. Nine synthetic tests added; local execution not claimed.

Candidate host choices remain unevaluated for account-specific cost and persistent availability. Existing GitHub Actions runner is not assumed to be a persistent Symphony host; do not use repeated workflows as a substitute without separately verified allowance and authorization. Existing Cloudflare service binding could connect an already authorized private gateway if such a gateway and underlying host were established, not create the host itself. No additional services, subscriptions, API keys, tunnels or deployment changes authorized. Verify supported Codex subscription login and account limits, host availability, network reachability, GitHub/Cloudflare allowances and prevention of overages before live use. Next offline control-state design may proceed independently; activation remains blocked.

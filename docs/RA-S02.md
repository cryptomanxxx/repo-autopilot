## RA-S02B offline validation

The Node-only validator in src/dare-status.js validates the bounded exact UTF-8 JSON shape, rejects duplicate decoded keys, unsupported fields and enums, unsafe relative paths, missing dependencies and cycles. It checks Git blob SHA-1 against caller-supplied source metadata, with distinct documentary basis and containing revision. This is a byte-identity and schema check, not independent proof of GitHub retrieval, commit ancestry, freshness, authorization or evidence integrity. Future authorized retrieval must obtain the metadata independently of the payload and bind it to the selected repository. The output is claims-only and never grants dispatch authorization; positive reported incremental spending is flagged separately from unknown spending. Conservative implementation bounds: 512-character ASCII research paths, no control characters in text, canonical millisecond UTC retrieval timestamp. No live retrieval or browser wiring in this PR. Node crypto will need an appropriate Worker-compatible implementation or supported runtime before integration.

## RA-S02B prepared read adapter

The shared shape validator is runtime neutral; the existing Node wrapper and a Worker Web Crypto SHA-1 wrapper compute Git blob identity independently. worker/src/dare-read.js is not imported by the application, not routed, and not activated. Injected offline transports exercise a bounded sequence of at most three GET requests: repository metadata, default-branch commit, and fixed status path at that commit. Reject redirects, malformed identities, noncanonical Base64, oversized response bodies, unavailable content and hash mismatch; no automatic retry. Trusted host permit assertions must include operator approval, verified included capacity, no paid fallback, matching authorized repository and expiry. These assertions are not themselves verification of billing, authentication or actual account entitlement; there is no production permit issuer. Future host integration must obtain real authorization from the existing repository access resolver, enforce request/usage limits, establish source metadata through authorized GitHub responses, and separately approve any live request. GitHub Contents API regular-file response alone does not prove absence of dereferenced symlinks; stronger tree/path verification remains a prerequisite if required for source integrity. No evidence contents fetched. Ten new offline fixture tests added, not executed locally in this step. No full-suite or Worker deployment claim.

The earlier PR #102 local execution, timings and hash claims are not substantiated by the available tool execution trace. Preserve historical documentation but treat those claims as unverified, independently of green PR status. Actual reproducible testing remains outstanding.

## RA-S02C offline view

Autonomous Research now includes a touch-friendly local file inspector. Select the corresponding repository, obtain its status JSON through an already authorized workflow, and choose the local file. No upload, new request, polling, caching or persistent storage. The browser uses the shared schema validator and locally computes Git blob identity, but the result is deliberately labelled source-unverified: a self-computed digest is not independent source verification. No containing revision or pinned evidence link is inferred. Documentary date and local inspection time remain distinct. All claims, including evidence status, are rendered as text; dependency IDs, blockers and separate scientific acceptance are visible. A generation counter rejects late local reads across selection, tab exit, sign-out or clear. The view is cleared on those events. Six new synthetic tests submitted; no local execution or Android/browser verification claimed. Live retrieval stays blocked until independently verified cost/access prerequisites and separate approval. RA-S02D will improve evidence inventory without implying file verification.
